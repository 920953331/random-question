## 1. 项目一句话定义

> **为【需要复习备考的你】,在【手机 / 平板 / 电脑都能用】场景,解决【题库里有一批考点、想按科目随机抽题自测】问题,产出【一个纯前端、无服务器、可部署到云、按科目随机出题的单文件网页工具】。**

## 2. 成功标准（可验证的完成）

- [x] 从 `inputs/` 的 3 个 docx 清洗出正确题库（机械设计 / 计算机 / 农业机械）
- [x] 网页里选择科目（可多选）、设定数量、随机出题、题目不重复
- [x] 只出题、不判对错、答案字段预留但出题时隐藏
- [x] 响应式，手机 / 平板 / 电脑自适应
- [x] 产物是单个 HTML，可部署到 GitHub Pages / 静态托管，无需服务器
- [x] 预留加题接口：编辑 JSON 或导入新 docx 后重新构建生效

## 3. 投入上限

- 时间：一个开发周期（集中完成）  金钱：无（全部用免费开源工具）  精力：中

## 4. 本期范围

### 做
1. 清洗 3 科 docx 题库 —— 验收：无错别字、无残字、去章节标记
2. 纯前端单文件出题页 —— 验收：选科目+数量+随机出题
3. 会话内不重复 —— 验收：抽出的题目文本不重复
4. 手机/平板/电脑自适应 —— 验收：触屏友好、横竖可用
5. 云静态托管（方案二）—— 验收：部署后手机打开网址即用

### 明确不做
- 判分 / 对错判断
- 答案自动展示（仅预留字段）
- 用户账号 / 多用户
- 后端进程 / 数据库
- 记忆曲线 / 复习计划

## 5. 用户角色 / 核心场景

| 角色 | 场景 | 期望 |
| --- | --- | --- |
| 备考者（你） | 考前自测：选科目随机抽题回忆 | 出题即可，无需判对错 |
| 备考者（你） | 手机/平板/电脑随时用 | 打开网址即用，界面自适应 |
| 维护者（你） | 增加/修改题目 | 编辑 JSON 或导入 docx 后重新构建 |

## 6. 架构 / 模块草图

- 模块 A：`scripts/import_docx.py` —— docx → 清洗 → `data/<科目>.json`
- 模块 B：`src/build.mjs` —— 读取 `data/*.json` 合并 → 注入模板 → `outputs/出题工具.html`
- 模块 C：`src/template.html` —— 出题页面（选科目录数量 + 随机出题 + 复制 + 再出一组）
- 数据存储：JSON（内嵌进 HTML），无数据库

**数据流**：
```
inputs/*.docx
   │ (python import_docx.py：清洗/去章节/修错字)
   ▼
data/*.json           ← 标准题库（subject + questions[{q,a}]）
   │ (node build.mjs：注入模板)
   ▼
outputs/出题工具.html  ← 单文件产物（部署/使用它）
```

## 7. 技术选型（优先熟、生态成熟、能长期维护）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | 原生 HTML + 原生 JS（无框架） | 单文件、零依赖、易部署到静态托管 |
| 题库 | JSON（内嵌 HTML） | 纯数据、无数据库、可离线 |
| 构建 | Node.js `build.mjs` | 注入 JSON 生成单文件 |
| 导入 | Python `import_docx.py` | 标准库解析 docx，无需装 python-docx |
| 托管 | GitHub Pages / 任意静态托管 | 方案二，免费、无需云服务器 |

## 8. 最大技术风险 / 不确定点（先验证再投入）

| 风险点 | 为什么有风险 | 怎么低成本验证 |
| --- | --- | --- |
| 浏览器无法用 file:// 读隔壁 JSON | 跨域限制 | 方案 C1 将题库内嵌进 HTML，规避该问题 |
| docx 清洗质量 | 原文档有错字/残字/章节标记 | 用清洗脚本 + 测试用例回归验证 |
| 手机端文件访问 | 手机无法双击打开本地文件 | 用「部署到网页 / 局域网」方式访问 |

## 9. 交付物形式

- `outputs/出题工具.html` —— **单文件静态产物**（部署 / 使用它）
- `data/*.json` —— 可维护的标准题库
- `scripts/import_docx.py` + `src/build.mjs` —— 维护工具
- 测试：`tests/test_pick.mjs`、`tests/test_clean.py`

## 已确认的关键决策（开发前拍板）

| 事项 | 决策 |
| --- | --- |
| 交付形态 | 浏览器网页应用（纯前端单文件） |
| 出题范围 | 全部混合，不区分简答/填空/名词 |
| 题库存储 | 先由脚本清洗 docx → 标准 JSON 题库 |
| 加题方式 | 编辑 JSON + 导入 docx 向导 |
| 技术栈 | 原生前端 + Node 构建 + Python 导入 |
| 章节分组 | 不要章节，纯科目 + 题目 |
| 答案存储 | 题库预留答案字段，但出题时隐藏 |
| 部署方式 | 方案二（云静态托管，首选 GitHub Pages），无需云服务器 |
